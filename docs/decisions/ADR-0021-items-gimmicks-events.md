# ADR-0021: フラグ、所持品とアイテムの能力、仕掛け、イベント

- Status: Accepted
- Date: 2026-11-25
- 論点: M3-3

## 背景

roadmap の M3-3 は「フラグ、イベント（トリガ / Condition / Action）、アイテムと `grants`、ゲートギミック」。受け入れ条件は「タグ無しで通れない → アイテム取得で通れる」「スイッチでフラグ → 扉が開く」の scenario と、`gating.subject` の 2 値。pack-spec の 4.3（`items.json`）、4.4（`gimmicks.json`）、4.5（`rules.json` の `inventory` と `gating`）、5.4（`gimmick` と `event` のオブジェクト）に形だけが決まっている。`World.flags` は M1 からあり、hash に入っている。

所有者の確認（2026-11-25）:

- 取ると通れるようになるアイテムは、岩を壊す道具「つるはし」（英語は Pickaxe）。持っていると、ひびの入った岩を剣で叩いて壊せる。
- アイテムは触れると拾う。拾ったら「つるはし を てにいれた」（Got the Pickaxe）を画面の下に 2 秒ほど出す。
- スイッチは壁のスイッチを剣で叩く。叩くと格子の扉が開く（一度開いたら開いたまま）。
- 拾ったアイテムはメニューの「もちもの」（Items）で確かめられる。何も無いときは「なにも もって いない」（Nothing yet）。使うアイテムはまだ無いので見るだけ。
- サンプルパックの流れ: 最初の部屋の上段の棚（左のはしごの上）につるはし → 下の通路の地下への扉の手前をふさぐ岩を壊す → 地下のワープの手前をふさぐ格子をスイッチで開ける → ワープで戻る。壊した岩と開いた扉は戻らない。
- 新しい絵（つるはし、ひびの入った岩、壁のスイッチの押す前と後、格子の扉）は所有者が Gemini で作り、決めた大きさに描き直す。届くまでは仮の絵でドラフトにする。

## 決定

### フラグ

- `World.flags` は文字列の名前から真偽値か整数への表（M1 のまま）。hash には名前の順で入る（M1 のまま）。
- 仕掛けの状態（拾った、壊した、押した、開いた）もフラグで持つ。名前を書かない仕掛けは、部屋と Tiled のオブジェクトの id から `obj:<roomId>:<objectId>` を自動で使う（Tiled のオブジェクトの id は部屋の中で変わらない）。
- 部屋を出入りしても、倒れて入口からやり直しても、フラグは消えない（セーブとロードは M3-5）。

### 所持品とアイテムの能力（`items.json`、`rules.inventory`）

- `items.json`（pack-spec 4.3）の `id`、`name`（`@strings:` 可）、`kind`、`grants?`、`stack`、`sprite` を読む。`effect`（回復など）は使うアイテムと一緒に後で読む（いまは読み込み時に拒否する）。
- `World.inventory`: アイテムの id から個数への表。`stack` を超えては持てない（超えた分は拾っても増えない）。hash にはフラグの後に、id の順で入る。
- `rules.inventory.scope` は `shared`（パーティで共有）だけを読む。`perCharacter` は M3-5（いまは読み込み時に拒否する）。
- **キャラクターの有効な能力タグ** = キャラクター自身のタグ ∪ 持っている（個数が 1 以上の）アイテムの `grants`。共有の所持品なので、全員に付く。タイルの通行（`requiresAnyTag`）、媒体の操作感、仕掛けと出口の条件は、すべてこの有効なタグで判定する（ADR-0007 の「アイテムで付与」をここで実装する）。

### ゲートの評価対象（`rules.gating.subject`）

- 仕掛けと出口の能力タグの条件（`breakable` の `requiresAnyTag`、出口の `requiresAnyTag`）を誰のタグで判定するか。
  - `active`: 操作中のキャラクターの有効なタグ（いまの出口と同じ）。
  - `anyInParty`: 倒れていないメンバーのだれかの有効なタグ。
- タイルの通行（体がそこを通れるか）は、いつも操作中のキャラクターの体で判定する（評価対象の対象外）。
- 無ければ `active`。サンプルパックは `active`。

### 仕掛け（`gimmicks.json` と部屋の `gimmick` オブジェクト）

部屋の `entities` レイヤの `gimmick` オブジェクト（`gimmickId`）が、`gimmicks.json` の定義を参照する。オブジェクトのプロパティで定義を上書きできる（pack-spec 5.4）。M3-3 で動く種類は 4 つ。ほかの種類（`door`、`savePoint`、`warp`、`text`、`spawner`、`bossDoor`）は、読み込み時に「まだ使えない」として拒否する。

| 種類 | パラメータ | 動き |
| --- | --- | --- |
| `pickup` | `itemId`、`count`（既定 1）、`onceFlag?` | 体が矩形に重なると拾う。所持品に足し、フラグを立てる。フラグが立っていれば出ない（拾い直せない） |
| `breakable` | `requiresAnyTag`、`flag?` | 壊れるまで矩形の中のタイルを壁（`full`）にする。剣の当たり判定（ADR-0017 の `hitbox`）が矩形に重なり、評価対象が `requiresAnyTag` のどれかを持っていれば壊れる（フラグを立てる）。持っていなければ何も起きない |
| `switch` | `setsFlag` | 剣の当たり判定が矩形に重なると、`setsFlag` を立てる（一度だけ。押した後の絵になる） |
| `gate` | `requiresFlag` | `requiresFlag` が立つまで、矩形の中のタイルを壁にする。立ったら開く（開いたまま）。`requiresAnyTag` と `consumesItem` は後で（いまは読み込み時に拒否する） |

- 壁になる仕掛け（`breakable`、`gate`）の矩形はタイルの格子に合わせる（読み込み時に検査する）。壁は衝突判定に足すだけで、部屋のタイルのデータは変えない（`CollisionContext` に閉じたセルを渡す）。開いた次の tick から通れる。
- 絵: `gimmicks.json` の各定義に `sprite: { atlas, frame }`、`switch` は押した後の `frameOn`。`pickup` はアイテムの `sprite`。壊れた岩、開いた格子、拾った後のアイテムは描かない。
- 剣で叩く判定は、その tick に出ている当たり判定の箱（`RenderSnapshot.hitboxes` と同じもの）で行う。

### イベント（`zones` レイヤの `event`）

- `trigger`: `onZoneEnter`（体が入った tick）、`onZoneExit`（出た tick）。入っているかどうかは部屋ごとに `World` に持つ（hash に入る）。部屋に入った tick に重なっていたゾーンは「入った」とする。
- `conditions`（すべて満たすとき）: `{ "flag": 名前, "is": 値 }`、`{ "hasItem": id, "count"?: n }`、`{ "notItem": id }`。
- `actions`（順に実行）: `{ "setFlag": 名前, "value"?: 値 }`、`{ "giveItem": id, "count"?: n }`、`{ "takeItem": id, "count"?: n }`。
- これ以外の条件と動作（会話、ワープ、敵の出現など）は使う機能と一緒に足す。サンプルパックでは使わない（テストで確かめる）。

### 出口の `requiresFlag`

- 出口（ADR-0018）の `requiresFlag` を読む。そのフラグが立っていない間は入れない（何も起きない）。

### システムの順（architecture.md 4.3）

- `interaction`（6）: HP の処理と出口の前に、拾う（体との重なり）、壊す・押す（剣の当たり判定との重なり）を、部屋の `gimmicks` の並び順で行う。
- `events`（7）: ゾーンの出入りを調べ、イベントを部屋の `zones` の並び順で実行する。
- 仕掛けとイベントで立てたフラグと増えたアイテムは、その tick の後の処理から効く（壁が開くのは次の tick の `movement` から）。

### 出力

- `StepOutput.notices`: その tick に起きた、画面に知らせること。`{ kind: 'pickup', itemId, count }`。描画の側（app）が「〜 を てにいれた」を約 2 秒出す（ゲームの時間ではなく画面の時間。止まっている間は進めない）。hash には入らない。
- `RenderSnapshot` の `sprites` に、出ている仕掛けの絵を足す。
- `UiState.inventory`: 持っているアイテムの id と個数（`items.json` の並び順）。メニューの「もちもの」が使う。

### ソルバー（ADR-0015）

- 壁になる仕掛けのある部屋では、閉じた壁を壁として探索し、高さと閉じた範囲の証明は出さない（開くと行ける範囲が広がるため）。拾う仕掛けとイベントは探索に入れない。鍵と扉のグラフ（A-3）で扱う（`docs/solver-handoff.md`）。

### hash（ADR-0002）

`flags` の後に `inventory`（id の順に id と個数）、その後に、いる部屋のゾーンの中にいるかどうかの列を足す。

## 結果

- 能力タグを付けるアイテムで、通れる場所と壊せるものが増える。フラグで仕掛けの状態がつながり、部屋を出入りしても残る。
- 入力のコマンド（ADR-0020）を使った「アイテムを使う」は、使うアイテムを作るときに足す。
