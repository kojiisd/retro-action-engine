## 1. いまの状態

`solveRoom(runtime, start, options)` が、パーティの各メンバーを 1 人ずつ解き、切替があるときはパーティ全体も解いて、`SolveReport` を返す。

| 報告 | 内容 | 根拠 |
| --- | --- | --- |
| `scopes` | キャラクター 1 人ずつ（`kind: 'character'`）と、切替があるときのパーティ（`kind: 'party'`） | パックのデータ（メンバーが 2 人以上で `mode: 'anywhere'`） |
| `status: 'reached'` と `witness` | 足場に着ける | 最初から再生して検証したリプレイ |
| `status: 'unreached'` | マクロと上限の範囲で見つからなかった | 探索の結果（不可能とは限らない） |
| `blocker`（`certainty: 'proven'`） | どんな入力でも着けない。`enclosed` か `tooHigh` | 証明（`proofs.ts`） |
| `blocker`（`certainty: 'estimated'`） | 見つからなかった理由の手がかり。`budget`、`needsTag`、`tooHigh`、`tooFar`、`unknown` | 推定 |
| `return.status: 'verified'` | 足場に最初に着いた状態から、開始の足場へ戻れる | 「行き + 帰り」のリプレイを再生して検証 |
| `return.status: 'provenNo'` | 足場の上のどの状態からも、どんな入力でも戻れない | 証明（`proofs.ts`） |
| `return.status: 'notFound'` | 最初に着いた状態からは、戻る経路が見つからなかった | 探索の結果 |
| `riseBound` | 接地から次の接地までに足元が上がる量の上限（上限なしや、証明を使えない規則では `null`） | `measureRiseBound`（ADR の「上昇量の上限」） |
| `proofs` | その対象で使えた証明（`region`、`height`） | ADR の「パーティでの証明」 |
| `complete: false` | 上限で打ち切った | |

- A-1 は PR 10（main に入っている）。
- A-2 は `claude/reachability-solver-a2`。A-2 の PR を main 向けに作る。A-3 は、A-2 が main に入ってから、main の新しいブランチで始める。

### 変えてはいけないこと

- **健全性のゲート**: 「到達できる」「戻れる」と報告するものは、必ず `verifyWitness`（`runReplayHeadless` で最初から再生し、足場の上に接地していること、hash が探索時の状態と同じこと）を通す。通らなければ例外にする。報告を弱めて通すことはしない。
- **物理は `step` だけ**: `step` を呼ぶのは `macros.ts` の `tick` と `probe.ts` だけ。エンティティの配列に書き込まない。`physics-guard.test.ts` がソースを検査している。`proofs.ts` はシミュレーションをしない。
- **証明は広く見積もる側にだけ倒す**: `proofs.ts` が「不可能」と言えるのは、行ける範囲を実際より広く見積もった外側だけ。根拠を ADR に書けないもの（新しい規則、新しいギミック）では、証明を出さない側に倒す（`proofRules`）。
- **証明と推定を混ぜない**: 推定は `EstimatedBlocker`（`certainty: 'estimated'`）。`ProvenBlocker` と `provenNo` に、探索や推定の結果を混ぜない。
- **証明と検証が食い違ったら例外**: 証明が「不可能」とした足場に検証済みのリプレイで着いた場合と、探索で実際に起きた足場間の移動を証明が否定した場合は `ProofError`。握りつぶさない。
- **証拠は探索木の親をたどって作る**: 同一視した節点への辺は、着地した状態が代表と少し違う。証拠の経路に使うと再生が一致しなくなる。目標つきの探索では、目標に着地したその状態（正確）までの入力を使う。
- **固有値を書かない**: キャラクター名、タグ名、速度、タイルサイズは `PackRuntime` から読む。テストの値は、テストファイルと `test-support.ts` に閉じる。
- **決定論**: 乱数と時計を使わない。走査順は固定（マクロの一覧の順、節点の id 順、足場の列挙順、タグの名前順）。

### 2.4 残っている見落とし（ADR の「完全性の範囲」）

- 空中での切替は試さない。
- 最も高く上がるのが先行入力のジャンプ（押下時間 0）の操作感では、最高点の足場を見落とす。先行入力のマクロ（落下中にジャンプを押して離し、着地と同時に跳ぶ）を足せば埋まる。
- 推定の `needsTag` は、タグを 1 つずつしか試さない。2 つ同時に要る場所は `tooFar` などになる。

## 3. これまでに分かったこと

A-1:

- 探索の速さは、おおよそ毎秒 130 万 step。空中制御と可変ジャンプがある操作感では、1 節点あたりのマクロが約 9 倍になる。部屋の広さより、操作感の自由度が効く。
- 開始位置が接地していれば、開始の足場の証拠は 0 tick のリプレイになる。
- 部屋の外は solid として扱われる。部屋の最上段のタイルの上には立てない（足場に数えない）。
- 踏み外しのマクロは、その節点からの「歩く」が足場を外れたときだけ試す。
- コヨーテタイムでしか届かない配置は、横の距離ではなく天井で作ると壊れにくい。
- 1px のタイルで部屋を作ると、高さを 1px 単位で指定できる（`tileSize: 1`）。

A-2:

- **全押しが最高とは限らない。** 頂点付近で重力が弱まる操作感では、カットで減速したほうが低重力の範囲に早く入り、高く上がることがある。標準の retro と modern では起きない。途中で離したときだけ上昇が止まらない操作感もある（頂点付近の重力が 0）。
- `moveBody` は、vy が 0 で足元がタイルの上面にちょうど乗っていれば、接地とみなす。
- 開始位置が空中のとき、`createWorld` は接地のフラグを立てない。最初の着地までは、何も押さずに落ちる。
- 証明の「立てる高さ」は、足場の一覧ではなく、支えになるタイルから作っている。
- 証明と検証の突き合わせ（`ProofError`）は、証明の誤りを見つけるのに有効だった。壊して戻す確認でも、証明を狭くする改変の多くが、ここで検出された。
- パーティでは、箱が違うメンバーへの切替で、箱が天井に入り込み、そこから上へ抜けられる（`moveBody` は重なっている行を調べない）。開いた領域の証明が成り立たないので、箱が全員同じときだけ証明を使う。
- タグが違うだけなら、切替で箱が「そのキャラクターにとって `full`」のセルに重なっても、証明は成り立つ（閉じたセルは全員にとって `full` のセルだけ）。
- パーティの探索は、1 人の探索の 3〜5 倍の `step` を使う。推定の解き直しもパーティの規模で行う。
- 推定の `needsTag` の前に、開いた領域で候補を絞る案は効かない。タグは領域を広げるだけなので、証明の付かない足場は、タグを足しても閉じたままにはならない。
- テストの実行時間は、1 つのファイルの長さで決まる（ファイルは並列に走る）。重いファイルは分ける。

## 4. 検証の方法

- **壊して戻す確認**: 改変を 1 つずつ入れて、ソルバーのテストが失敗することを確かめる。A-1 で 19 件、A-2 で 90 件（前半 36 件、後半 54 件）を行った。結果は下の表。足す機能にも同じ確認をする。
- **実行時間**: ソルバーのテスト全体は約 8 秒（134 件）。10 秒以内を保つ。
- **PR 本文に書くこと**: fixture ごとの節点数と `step` の回数、「状態を変えるのは `step` と `cloneWorld` だけ」であること、証明の根拠が ADR のどこにあるか、壊して戻す確認の結果。

### A-1 の壊して戻す確認（19 件、すべて検出）

- ゲート: 足場の確認を外す、hash の確認を外す、`solveRoom` がゲートを呼ばない、押した瞬間を入れない。
- 探索: キーから x を外す、キーから y を外す、節点数の上限を外す。
- マクロ: コヨーテのジャンプを外す、遅延 0 だけにする、すり抜け降下を外す、最長の押下時間を外す、押下を 1 tick 短くする、歩くを外す、`step` の上限を外す、tick の上限を外す。
- 足場: タグを無視する、接地の確認を外す。
- 対象: 1 人に絞らない。実測の上昇の tick 数を短くする。
