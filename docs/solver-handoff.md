# 到達可能性ソルバー: A-2 の残りへの引き継ぎ

A-1（キャラクター 1 人ずつの到達可能性）と、A-2 の前半（キャラクター 1 人の範囲での「証明」）を終えた時点の状態と、残りの作業をまとめる。設計の根拠は [ADR-0015](decisions/ADR-0015-reachability-solver.md)、受け入れ条件は [roadmap.md](roadmap.md) の「A: 解析ツール」にある。本メモと ADR が食い違う場合は、ADR を先に直す。

A-2 が終わったら、このファイルは削除するか、A-3 への引き継ぎに書き換える。

## 1. いまの状態

`solveRoom(runtime, start, options)` が、パーティの各メンバーを 1 人ずつ解いて `SolveReport` を返す。

| 報告 | 内容 | 根拠 |
| --- | --- | --- |
| `status: 'reached'` と `witness` | 足場に着ける | 最初から再生して検証したリプレイ |
| `status: 'unreached'` | マクロと上限の範囲で見つからなかった | 探索の結果（不可能とは限らない） |
| `blocker`（`certainty: 'proven'`） | どんな入力でも着けない。`enclosed` か `tooHigh` | 証明（`proofs.ts`） |
| `return.status: 'verified'` | 足場に最初に着いた状態から、開始の足場へ戻れる | 「行き + 帰り」のリプレイを再生して検証 |
| `return.status: 'provenNo'` | 足場の上のどの状態からも、どんな入力でも戻れない | 証明（`proofs.ts`） |
| `return.status: 'notFound'` | 最初に着いた状態からは、戻る経路が見つからなかった | 探索の結果 |
| `riseBound` | 接地から次の接地までに足元が上がる量の上限（上限なしは `null`） | `measureRiseBound`（ADR の「上昇量の上限」） |
| `complete: false` | 上限で打ち切った | |

ブランチと PR:

- A-1 は `claude/reachability-solver`（PR 10）。
- A-2 の前半は `claude/reachability-solver-a2`（A-1 のブランチから切った。PR は未作成）。残りの作業は、このブランチの続きで行う。
- 2026-11-16 時点の状態である。A-1 の PR が main に入ったあとは、main を A-2 のブランチに取り込んでから続ける（main は squash マージなので、A-1 のコミットは別のコミットとして入る。内容が同じなので、取り込みで衝突したら A-2 側を採る）。

まだ無いもの: 切替とパーティ全体の探索、推定の理由、操作感の Property テスト、M3 への拡張設計の詳細化、上限の見直し。

### 変えてはいけないこと

- **健全性のゲート**: 「到達できる」「戻れる」と報告するものは、必ず `verifyWitness`（`runReplayHeadless` で最初から再生し、足場の上に接地していること、hash が探索時の状態と同じこと）を通す。通らなければ例外にする。報告を弱めて通すことはしない。
- **物理は `step` だけ**: `step` を呼ぶのは `macros.ts` の `tick` と `probe.ts` だけ。エンティティの配列に書き込まない。`physics-guard.test.ts` がソースを検査している。`proofs.ts` はシミュレーションをしない。
- **証明は広く見積もる側にだけ倒す**: `proofs.ts` が「不可能」と言えるのは、行ける範囲を実際より広く見積もった外側だけ。見積もりを狭くする変更（oneway を壁として扱う、横の位置を考慮する、など）は、根拠を ADR に書いてから入れる。
- **証明と推定を混ぜない**: 推定の理由は `certainty: 'estimated'` の別の型として足す。`ProvenBlocker` に推定を足さない。`provenNo` に探索の結果を混ぜない。
- **証明と検証が食い違ったら例外**: 証明が「不可能」とした足場に検証済みのリプレイで着いた場合と、探索で実際に起きた足場間の移動を証明が否定した場合は `ProofError`。握りつぶさない。
- **証拠は探索木の親をたどって作る**: 同一視した節点への辺は、着地した状態が代表と少し違う。証拠の経路に使うと再生が一致しなくなる（ゲートで例外になる）。目標つきの探索では、目標に着地したその状態（正確）までの入力を使う。
- **固有値を書かない**: キャラクター名、タグ名、速度、タイルサイズは `PackRuntime` から読む。テストの値は、テストファイルと `test-support.ts` に閉じる。
- **決定論**: 乱数と時計を使わない。走査順は固定（マクロの一覧の順、節点の id 順、足場の列挙順）。

## 2. 残りの作業

順番に進める。各項目の終わりで `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm depcruise` を通し、コミットして push する。

### 2.1 切替のマクロとパーティの探索

目的: 2 人を切り替えながら行ける範囲を求める。「片方だけが届く足場」に、切替を使えばパーティとして届くことを示す。

- 対象: `Scope` に `{ kind: 'party', members }` を足す。`solveRoom` は、1 人ずつの結果に続けて、メンバーが 2 人以上で `canSwitch` が真のときだけパーティの結果を返す（1 人構成や `mode: 'never'` では出さない。データから導く）。
- マクロ: `{ kind: 'switch' }`。切替の cooldown（`world.party.cooldownTicks`）が 0 になるまで何も押さずに待ち、切替を 1 tick 押す。切替が起きたかどうかは `world.party.activeIndex` の変化で見る。変わらなければ `skipped`。
  - `requireGrounded` が真の規則では、接地中にしか切り替わらない。マクロは接地状態から始まるので、そのまま使える。
  - `placement: 'spawn'` の規則では、切替で位置が入口の spawn に移る。`step` の結果をそのまま節点にすればよい（ソルバーは位置を計算しない）。
  - 切替で当たり判定の箱が変わる。箱が壁に重なる場合の挙動は core の実装どおりで、ソルバーは `step` の結果を使うだけにする。切替の直後に接地していなければ、着地まで待つ。
- 空中での切替: `requireGrounded` が偽なら、ジャンプ中に切り替えられる。まず接地中の切替だけを実装し、テストが通ってから「ジャンプの頂点で切替」を足す。足さない場合は、ADR の「完全性の範囲」に「空中での切替は試さない」と書く。
- キー: 「操作中のキャラクターの番号、足元の高さ、x の量子、vx の量子、cooldown が残っているか」。`search.ts` の `keyOf` を広げる。
- マクロの一覧: 操作感はキャラクターごとに違いうる（`CharacterDef.feelOverrides`）。`explore` の冒頭で 1 回だけ作っている `baseMacros` と `holds` を、操作中のキャラクターごとに作って引くようにする（`measureRise` もキャラクターごと）。
- 足場: パーティでは「誰かが立てる足場」をすべて数える。`FootholdIndex` はメンバーごとの足場を持っているので、パーティの報告では「部屋のタイルの並び」に束ね直す。
- 証拠: `replayFromHelds` に渡す `StartState.party` を、パーティのメンバー全員にする。`verifyWitness` に渡すキャラクターは、終端で操作中のキャラクターにする。

**パーティでの証明（要注意）**: ADR の「上昇量の上限」の根拠は「キャラクター 1 人、動かないタイル」を前提にしている。パーティに広げるときは、次を ADR に書いてから実装する。

- 開いた領域: 切替で箱とタグが変わる。「誰かが通れれば空き」とし、開始時の箱は全メンバーの箱で調べる。切替で箱が `full` のタイルに重なりうる（箱の大きさが違う場合）なら、「箱は `full` に重ならない」という前提が崩れるので、`enclosed` の証明を出さない。
- 上昇量の上限: 空中で切り替えると、ジャンプの途中で操作感が変わる。根拠の 3（vy はカットの tick だけで決まる）が成り立たなくなる。メンバーの操作感の最も有利な値を組み合わせた仮の操作感で測る案は、頂点付近の重力倍率の非単調性（ADR の「全押しが最大とは限らない」）があるので、そのままでは上限にならない可能性がある。`requireGrounded` が真の規則なら、接地中にしか切り替わらないので、メンバーごとの `riseBound` の最大値を使える。偽の規則では、根拠を作れるまで `tooHigh` と `provenNo` を出さない（`riseBound` を `null` にする）のが安全。
- `placement: 'spawn'` の規則では、切替で位置が移る。高さの証明（`tooHigh`、`provenNo`）は使えない。`enclosed` は、spawn が開いた領域の中にあるので使える。

テスト（fixture）:

- 「片方だけが届く足場」: 1 人ずつではどちらも届かず、パーティでは届く配置を作る。現在の `WALKER` と `SWIMMER` は箱と操作感が同じなので、`test-support.ts` にキャラクターごとの箱や `feelOverrides` を渡せるようにする。
- `cooldownTicks` の間は切り替わらないこと、`mode: 'never'` と 1 人構成ではパーティの結果が出ないこと。
- 証拠のリプレイに切替の入力が含まれ、再生で足場に着くこと。
- ランダムな部屋での突き合わせ（`solve.random.test.ts`）に、切替の入力を足す。

### 2.2 推定の理由

目的: 証明が付かない `unreached` の足場に、推定の理由を付ける。

- 型: `Blocker` に `EstimatedBlocker`（`certainty: 'estimated'`）を足す。`ProvenBlocker` は変えない。報告を読む側が `certainty` で分岐できるようにする。
- `needsTag`: 部屋のタイルクラスに現れるタグを 1 つずつ足した仮のキャラクターで解き直し、届けばそのタグを理由にする。解き直しの回数だけ予算を使う。先に `Proofs` で「そのタグがあれば `enclosed` でなくなるか」を見て、候補を絞るとよい。
- `tooHigh`（推定）と `tooFar`: 到達できた足場の上面と、目的の足場の上面の差を、全押しの実測の上昇量（`measureRise`）と比べる。不足分を px で出す。証明の `tooHigh`（`riseBound` を使う）とは別物なので、名前か型で区別する。
- `budget`: `complete: false` のとき。
- `unknown`: どれでもない。

テスト（fixture）: タグの壁の向こうが `needsTag`（いまは `enclosed` の証明が付く。タグを持つ仮のキャラクターで届くことを足す）、上限を小さくすると `budget`、証明つきの足場には推定を付けないこと。

### 2.3 操作感の Property テスト

目的: 操作感を変えたときに、届く足場が操作感の値から導いた結果どおりに変わることを確かめる。

- `fast-check` は `solver` の devDependency に入っている。`rise-bound.test.ts` と `solve.random.test.ts` が使い方の見本になる。
- 高さ: `jumpVelocity` と `gravity` をランダムに選ぶ（1/256 px の倍数）。`solve.test.ts` の `riseInPx` と同じ式で上昇量を出し、`floor` の高さの棚は届き、1px 高い棚は届かず `tooHigh` の証明が付くことを確かめる。
- コヨーテ: `coyoteTicks` を増やしても、届く足場の集合が減らないこと（単調性）。A-1 のコヨーテの fixture（天井つきの通路）を使える。
- 上限に注意: ソルバーのテスト全体で 10 秒以内に収める。`numRuns` を絞る。

### 2.4 最高点に届く押下時間をマクロに足す

A-2 の前半で分かった取りこぼし。頂点付近で重力が弱まる操作感では、全押しより、途中で離したジャンプのほうが高く上がることがある（ADR の「上昇量の上限」）。`jumpHolds` は全押しを必ず含むが、最大になる押下時間は含むとは限らない。

- `measureRiseBound` が最大を出した押下時間を返すようにし、`jumpHolds` に必ず含める。
- 押下時間 0（先行入力で、ボタンを離したまま始まるジャンプ）が最大の場合は、マクロでは作れない（マクロは接地状態から始まる）。その場合は ADR の「完全性の範囲」に書く。
- テスト: `rise-bound.test.ts` の `earlyRelease` の操作感で、上限ちょうどの高さの棚に届くこと。

### 2.5 M3 への拡張設計の詳細化

目的: ADR-0015 の「M3 への拡張」を、A-3 で実装できる粒度にする。実装はしない。

- 鍵と扉のグラフの節点と辺の型の案。
- 単調に増える状態（`grants`、フラグ）の不動点の計算手順と、止まることの根拠。
- 単調でないもの（鍵の消費、一方通行の exit、敵、移動床）の扱いの案。動く床や、体を上に運ぶ仕掛けが入ると、「上昇量の上限」の根拠 1 と 5 が崩れる。証明をどう保つかを書く。
- 部屋をまたぐ証拠のリプレイのつなぎ方。「戻れる」の戻り先（開始の足場）を、部屋をまたぐ場合にどう決めるか。
- `docs/pack-spec.md` の exits、アイテム、フラグの定義を読み、食い違いがあれば「要確認」に書く。

### 2.6 上限の見直し

- 戻りの探索が入ったので、`step` の総回数は「到達できた足場の数」に応じて増える。パーティの探索を入れたあとで、ADR の実測の表を取り直す。
- 既定の `maxNodes`（20,000）と `maxSteps`（20,000,000）を、実測に合わせて見直す。
- 戻りの探索は、戻れない領域（`notFound`）の足場ごとに、その領域全体を探索し直す。領域が広いと重い。足場ごとに予算を分ける案を検討する。

## 3. これまでに分かったこと

A-1:

- 探索の速さは、おおよそ毎秒 130 万 step。空中制御と可変ジャンプがある操作感では、1 節点あたりのマクロが約 9 倍になる。部屋の広さより、操作感の自由度が効く。
- 開始位置が接地していれば、開始の足場の証拠は 0 tick のリプレイになる。
- 部屋の外は solid として扱われる。部屋の最上段のタイルの上には立てない（足場に数えない）。
- 踏み外しのマクロは、その節点からの「歩く」が足場を外れたときだけ試す。
- コヨーテタイムでしか届かない配置は、横の距離ではなく天井で作ると壊れにくい。
- 1px のタイルで部屋を作ると、高さを 1px 単位で指定できる（`tileSize: 1`）。

A-2 の前半:

- **全押しが最高とは限らない。** 頂点付近で重力が弱まる操作感では、カットで減速したほうが低重力の範囲に早く入り、高く上がることがある。標準の retro と modern では起きない。
- `moveBody` は、vy が 0 で足元がタイルの上面にちょうど乗っていれば、接地とみなす。ジャンプの頂点で oneway の上面にちょうど止まった場合も接地になる。
- 開始位置が空中のとき、`createWorld` は接地のフラグを立てない（足元にタイルがあるときだけ立つ）。最初の着地までは、何も押さずに落ちる。
- 証明の「立てる高さ」は、足場の一覧ではなく、支えになるタイルから作っている。足場の一覧は 1px 刻みで箱が収まるかを見るので、そこから漏れた場所を証明の側で排除しないためである。
- 「戻れる」の探索は、開始の足場が広い床なら数手で終わる。重くなるのは、戻れない領域の足場である（領域全体を探索してから `notFound` になる）。先に `provenNo` を調べると、深い穴ではそもそも探索しない。
- 証明と検証の突き合わせ（`ProofError`）は、証明の誤りを見つけるのに有効だった。壊して戻す確認でも、証明を狭くする改変の多くが、ここで検出された。

## 4. 検証の方法

- **壊して戻す確認**: 改変を 1 つずつ入れて、ソルバーのテストが失敗することを確かめる。A-1 で 19 件、A-2 の前半で 36 件を行った。結果は下の表。足す機能にも同じ確認をする。
- **実行時間**: ソルバーのテスト全体は約 8 秒（93 件）。10 秒以内を保つ。
- **A-2 の PR 本文に書くこと**: fixture ごとの節点数と `step` の回数、「状態を変えるのは `step` と `cloneWorld` だけ」であること、証明の根拠が ADR のどこにあるか、壊して戻す確認の結果。

### A-1 の壊して戻す確認（19 件、すべて検出）

- ゲート: 足場の確認を外す、hash の確認を外す、`solveRoom` がゲートを呼ばない、押した瞬間を入れない。
- 探索: キーから x を外す、キーから y を外す、節点数の上限を外す。
- マクロ: コヨーテのジャンプを外す、遅延 0 だけにする、すり抜け降下を外す、最長の押下時間を外す、押下を 1 tick 短くする、歩くを外す、`step` の上限を外す、tick の上限を外す。
- 足場: タグを無視する、接地の確認を外す。
- 対象: 1 人に絞らない。実測の上昇の tick 数を短くする。

### A-2 の前半の壊して戻す確認

36 件の改変を 1 つずつ入れ、ソルバーのテスト全体を回した（2026-11-16）。

| 上限 | カットの tick の前半しか試さない | 最初は検出できず。最大になるのが後半の操作感のテストを足して検出 |
| 上限 | 最大ではなく最小を取る | 検出 |
| 上限 | 重力の符号の確認を外す | 最初は検出できず。テストを足して検出（下の注） |
| 上限 | fall 時の重力倍率の符号の確認を外す | 検出 |
| 上限 | 頂点付近の重力倍率の符号の確認を外す | 最初は検出できず。テストを足して検出（下の注） |
| 上限 | `maxFallSpeed` の符号の確認を外す | 検出できない。振る舞いが変わらない改変（下の注） |
