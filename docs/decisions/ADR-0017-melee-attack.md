# ADR-0017: 剣を振る攻撃（攻撃の動きと当たり判定の箱）

- Status: Accepted
- Date: 2026-11-21
- 論点: M2-5 の後半（M3-4 の一部の前倒し）

## 背景

所有者の判断（2026-11-20）で、攻撃モーションを M3 から前倒しする。M2-5 の前半（HP と水、ADR-0016）はマージ済み。

所有者の確認（2026-11-21）:

- 攻撃は剣を振るもの。絵は 3 コマ（構え、振り、戻り）で、2 人とも振れる。
- 振っている間、地上ではその場で止まる（空中ではそのまま飛び続ける）。操作感のデータで切り替えられるようにしておく。
- 攻撃のコマだけ絵の大きさを 32×24 にする（体はいまの 16×24 と同じ位置で中央に置き、前後 8 ドットずつに剣を描ける）。
- スマホの仮想パッドに攻撃ボタンを足し、印は剣の形にする。
- 絵は所有者が生成して渡す。届くまでは仮の絵で進め、差し替えてからマージする。

まだ敵がいない（M3-4）ので、攻撃が何かに当たって起きること（ダメージ、ノックバック、無敵時間）はこの ADR の範囲外とする。ここでは「振る動き」と「当たり判定の箱（hitbox）をいつどこに出すか」までを決める。

docs には、攻撃を状態ではなくフラグ（残り tick）として空中でも出せること（input-and-feel.md 8.4）、アニメーションの各コマに `hitbox` を書けること（pack-spec.md 4.1）が、すでに決まっている。

## 選択肢

攻撃の長さをどこに書くか。

| 案 | 概要 | 長所 | 短所 |
| --- | --- | --- | --- |
| 1 | 操作感プロファイルに攻撃の長さ（tick）を書く | 操作感をまとめて調整できる | 絵のコマの長さと二重に書くことになり、ずれる |
| 2 | キャラクターの `attack` アニメーションのコマの長さの合計を、攻撃の長さとする。当たり判定の箱もそのコマに書く | 絵と判定が 1 か所にまとまり、ずれない。キャラクターごとに違う振り方ができる | 攻撃の調整が絵のデータの編集になる |

## 決定

案 2 を採る。

### パックのデータ

- **攻撃できるキャラクター**: `characters.json` の `sprite.animations` に `attack` があるキャラクターは攻撃できる。無いキャラクターは攻撃の入力を無視する（キャラクター ID では分岐しない）。
- **攻撃の長さ**: `attack` アニメーションの全コマの `ticks` の合計。`attack` は `loop: false` でなければならない（読み込み時に検査する）。
- **当たり判定の箱**: `attack` の各コマの `hitbox?: { x, y, w, h }`（px、足元中央から、右向きのとき）。左向きのときは左右を反転する（`x' = -(x + w)`）。`hitbox` の無いコマでは箱を出さない（構えと戻り）。
- **絵の大きさ**: コマごとに違ってよい。描画は足元中央を基準に置く（`setOrigin(0.5, 1)`）ので、32×24 の攻撃のコマも、体が 16×24 のコマと同じ位置に来る。
- **操作感**: `feel.json` の各プロファイルに `attackOnGround?: 'stop' | 'move'`（無ければ `stop`）。

### 動き（`controller`）

- `inputIntent` が `attack` の押下（その tick に押された）を攻撃の要求にする。先行入力は持たない（必要になったら操作感に足す）。
- 攻撃していない、着地硬直（`landingLagTicks`）中でない、攻撃できるキャラクターのときに攻撃を始める。空中でも、水の中でも出せる。
- `World.controller` に `attackUntilTick` を足す（攻撃していないときは `NEVER`）。開始した tick を `t` として `t + 攻撃の長さ` を入れ、`tick < attackUntilTick` の間が攻撃中。
- 攻撃中は向きを変えない（振っている途中で振り向かない）。
- 攻撃中に地上にいて `attackOnGround` が `stop` なら: 横の速度を 0 にし、左右の入力とジャンプを受け付けない（その場で止まる）。空中では、これまでどおり重力と空中制御が働く（そのまま飛び続ける）。
- 交代したとき、倒れたとき、入口からやり直したときは、攻撃を打ち切る。

### アニメーションと出力

- 攻撃中は、移動の状態（`idle`、`run`、`jump`、`fall`）より `attack` を優先して出す。攻撃を始めた tick に `attack` の 0 コマ目から始める。
- `RenderSnapshot` に `hitboxes`（いま出ている当たり判定の箱、px、ワールド座標）を足す。デバッグ表示（当たり判定の枠、開発と PR のプレビューだけ）で、体の箱とは別の色で描く。スナップショットは hash に入らない。
- 箱が何に当たるか（敵、壊せる壁）は M3-4 で決める。

### hash（ADR-0002）

`controller` の `rightPressedTick` の後に `attackUntilTick`（int32）を足す。

### 入力の割り当てと仮想パッド（ADR-0008）

- サンプルパックの `input.json`: キーボードは `KeyX`、標準ゲームパッドは `button2`（pack-spec.md 4.7 の例と同じ）。
- 仮想パッドの `attack` のボタンは、剣の形の印（上向きの剣を単純な図形で描いた白い影絵。既存の 2 つと同じ描き方）。サンプルパックのレイアウトに攻撃のボタンを足す。

## 結果

- 敵（M3-4）は、この `hitboxes` と敵の `hurtbox` の重なりで判定するだけでよい。
- `World` が変わるので golden を更新する（PR 本文に理由を書く）。
- 仮の絵で作った攻撃のコマは、所有者の絵に差し替えてからマージする（PR はそれまでドラフト）。

## 要確認

- 攻撃の各コマの長さと当たり判定の箱の値は、仮の値で入れる。所有者の絵が届いたら、絵に合わせて決め直す。
- 振っている途中のジャンプ（空中で振り始めたまま着地したとき）は、着地した時点から「その場で止まる」になる。違和感があれば調整する。
