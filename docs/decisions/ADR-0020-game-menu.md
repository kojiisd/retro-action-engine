# ADR-0020: ゲーム内のメニュー

- Status: Accepted
- Date: 2026-11-25
- 論点: M3-6（M3-6a と M3-6b に分ける）

## 背景

所有者の要望（2026-11-23）で、ゲーム内のメニューを足す。roadmap では所持品（M3-3）とセーブ（M3-5）の後に置いていたが、所有者の判断（2026-11-24）で先に作り、所持品とセーブは後からメニューに足す。いまの `menu` ボタンと HUD の歯車は、HTML の設定画面（M2-2）を開く。

所有者の確認（2026-11-24〜25）:

- 第 1 版の中身は「パーティ」「ちず」「せってい」と、閉じる項目。「入口からやり直す」はメニューに入れず、アイテムで扱う（M3-3）。
- **パーティ**: 2 人のアイコン、名前、HP を出し、**選ぶとそのキャラクターに交代する**（交代の条件はいまと同じ）。
- **ちず**: 行ったことのある画面だけを塗る。地図のアイテムを手に入れたら、行っていない場所も含めて全体が見える（M3-6b。アイテムは M3-3）。
- **見た目**: ゲームと同じドット絵の窓をゲーム画面の中に出す。枠とカーソルは見本の単純な図形（白い縁、紺の地、白い ▶）のまま使い、色はパックのデータで変えられる。
- **文字**: ドットの日本語フォント。M+ BITMAP FONTS の 12 px（M+ FONT LICENSE。使う、複製する、改変する、配る、商用で使う、のすべてが自由）。項目名はひらがなで「パーティ」「ちず」「せってい」「とじる」（英語のブラウザでは Party / Map / Settings / Close）。窓の下に、選んでいる項目の説明を 1 行出す。
- **名前**: 2 人に名前を付ける。日本語は「ソラト」「ミナモ」、英語は「Sorato」「Minamo」。名前はパックのデータで変え、ゲームの中では変えない。6 文字まで。
- フォントのライセンス（2026-11-25）: M+ FONT LICENSE のまま使い、表記を実態どおりにする。フォント画像は CC0 と書かない（権利者は M+ FONTS PROJECT）。`pack.json` の `licenses.assets` を「CC0-1.0 (except ui/font.png: M+ FONT LICENSE, see credits.json)」にし、`credits.json` に権利者の表示とライセンスの全文を書き、CLAUDE.md の「素材は CC0 のみ」にこのフォントを例外として足す。
- PR を 2 つに分ける。M3-6a: 窓、フォント、開け閉めと操作、パーティ、設定への入口。M3-6b: 地図。

## 決定

### 開け閉め

- `menu` の押下で開き、もう一度押すと閉じる。HUD の歯車（タッチ向け）もメニューを開く（これまでは設定画面を開いていた）。
- 開いている間は時間を止める（設定画面と同じく、`GameSession` に 0 ms を渡す）。閉じた後は、入力を「すべて離した」状態から始める（設定画面と同じく、閉じたときに `InputBuffer.focusLost()` を呼び、押したままの `menu` は離すまで無視する）。
- メニューを開いている間も入力は生きている（メニューの操作に使う）ので、閉じた時点で押されていたボタンは、一度離すまでゲームに渡さない（apps/player の `HoldGate`。離したかどうかはデバイスの状態で決める）。押したまま閉じた方向キーで、閉じた途端にキャラクターが歩き出さないようにするため。設定画面を閉じたときも同じにする。
- 1 つの描画フレームに複数の押下が届いても、届いた順に処理する（「決める」の後の「下」が先に効かないように）。
- 部屋の移動の途中（暗転中）でも開ける。

### 操作

- 上下で項目を選ぶ。`confirm` か `jump` で決める。`cancel` か `attack` で 1 つ戻る（いちばん上の階層では閉じる）。`menu` はどこからでも閉じる。
- ボタンの割り当ては、ゲームの操作と同じ `input.json` の割り当てをそのまま使う（メニューのためにキーを足さない）。タッチでは方向パッドとジャンプ、攻撃のボタンで操作し、歯車で閉じる。
- 操作は押下（その描画フレームで押された）で進める。押しっぱなしの繰り返しは無い（項目が少ないため）。

### 画面の構成（320×180 のゲーム画面の場合の例。位置と大きさは画面の大きさから決める）

- 左の窓: 項目の一覧。いま選んでいる項目の左に ▶。
- 右の窓: 選んだ項目の中身。いちばん下の行に説明を 1 行。
- パーティ: メンバーごとに、待機の 0 コマ目の絵、名前、HP のゲージと数字（`現在/最大`）。いま操作しているメンバーの名前は強調の色。交代できないメンバーは薄い色。
- 説明の 1 行は、選んでいる項目で変わる。パーティでは、交代できるとき「えらぶと こうたい します」、できないときはその理由（いま操作している、倒れている、地上でないと交代できない、待ち時間が残っている、このパックでは交代できない）。
- メニューの文言（項目名、説明）は app 層の `ui-strings.ts`（日英）に置く。公開する文言なので、変えるときは所有者の確認を取る。

### 交代のコマンド（core）

メニューから「このメンバーに交代」を伝えるため、入力に**コマンド**を足す。リプレイとブラウザと Node の一致を保つため、コマンドも入力として記録する。

- `InputFrame.command?: number`。無い、または 0 なら何もしない。`(種類 << 8) | 引数` の整数で、種類 1 が「交代先を指定した交代」（引数はパーティのメンバーの番号）。ほかの種類は後の ADR で足す（M3-3 のアイテムを使う、など）。
- `party` システムが、交代ボタンの押下と同じ位置で処理する。条件も交代ボタンと同じ（`switch.mode`、`requireGrounded`、待ち時間、倒れていない）に加えて、指定したメンバーがいま操作しているメンバーでないこと。条件を満たさなければ何もしない。同じ tick に交代ボタンも押されていれば、コマンドを優先する。
- core に `switchCheck(world, runtime, index)` を足す。結果は `ok`、`active`、`down`、`never`（交代できないパック）、`airborne`、`cooldown`。メニューはこれで説明の 1 行と薄い表示を決め、`ok` のメンバーを選んだときだけメニューを閉じてコマンドを送る。
- `GameSession.queueCommand(command)`: 次に進める tick の入力にコマンドを付ける（メニューを閉じた後の最初の tick）。
- リプレイ: `frames` の各要素に 5 つ目の値 `command` を足す（0 なら省略）。`version` を 2 にし、`version: 1` のファイルも読める（`command` は 0）。`Recorder` は `command` も含めて同じフレームをまとめる。

### 名前（pack）

- パック仕様 4.10 の `strings.<lang>.json` と `@strings:key` の参照を実装する（manifest の `files.strings`）。キャラクターの `name` は文字列か `@strings:key`。言語の選び方は app 層（ブラウザの言語。そのパックに無ければ既定の言語）。
- 名前は 1〜6 文字（Unicode のコードポイントで数える）。どの言語でも超えていたら読み込み時のエラー。6 はメニューの窓の幅から決めた仕組みの定数。

### フォントと窓の色（pack）

- パックの `data/ui.json`（manifest の `files.ui`、任意）に置く。
  - `font`: 画像（`image`）、セルの大きさ（`cellW`、`cellH`）、ベースライン（`ascent`）、文字の一覧（`glyphs`: 文字と幅の組の配列。画像の左上から行ごとにセルを並べた順）。
  - `colors`: 窓の縁、窓の地、文字、強調の文字、薄い文字、カーソル、HP のゲージ（中身と地）。`#rrggbb`。
- フォントに無い文字は `?` の字形で描く。サンプルパックのフォントは、メニューの文言、キャラクターの名前、数字と記号をすべて含む（テストで確かめる）。
- `ui.json` が無いパックではメニューを開かない（`menu` と歯車はこれまでどおり設定画面を開く）。
- サンプルパックのフォント画像は、M+ BITMAP FONTS の `mplus_j12r`（全角）と `mplus_f12r-jisx0201`（半角）から、使う文字だけを元のドットのまま書き出したもの。書き出しの道具は `scripts/font`（BDF を読み、文字の一覧を受け取って PNG と JSON を書く）。BDF そのものはリポジトリに置かず、出所とライセンスを `credits.json` に書く。M+ FONT LICENSE には表示の義務は無いが、出所を明らかにするために書く。

### 描画（renderer-phaser と apps/player）

- メニューの状態（開いているか、どの階層のどの項目か）と、そこから作る表示モデル（窓、文字、絵、ゲージ、カーソルの位置と色）は apps/player の純粋な関数で作り、テストする。
- renderer-phaser は表示モデルを受け取って描くだけ（窓の矩形、フォント画像からの文字、アトラスの絵、ゲージ）。文字の並べ方（字形の番号と幅）は、描く側と置く側の両方が使うので `pack` の `font.ts` に置く。ゲームの画面の上、HUD の上に重ね、カメラに付いて動かない。メニューを開いている間は、後ろのゲームの画面を少し暗くする。
- 「せってい」を選ぶと、いまの HTML の設定画面を開く。設定画面を閉じるとメニューに戻る。

### 地図（M3-6b。2026-11-28 の改訂で決めた）

所有者の確認（2026-11-28）: 画面ごとのマス、出口の印も出す、地図のアイテムは「ちず」/「Map」で `hub` の上段の右の棚（右のはしごの上）、説明の 1 行は「いま いる へやの ちず」/「Map of this room」。

- **画面**: 部屋をプレイ領域の大きさ（`display` から `hudReserve` を除いたもの。カメラの無いパックでは部屋全体）で区切ったマス。部屋の端が画面の途中で終わるときは、その分もマスにする（切り上げ）。サンプルの `hub` は横 5 × 縦 3、`cellar` は 1。
- **行った画面**（core）: 体（当たり判定の箱）の中心があるマスを「行った」とする。`World.visited`（部屋の id から、行ったマスの番号（行 × 列数 + 列）の昇順の列への表）。`camera` システムの後で、その tick の体の位置で記録する（architecture.md 4.3）。部屋に入った tick（開始、出口、入口からのやり直し）も記録する。hash は `zonesInside` の後に、部屋の id の順に id、個数、番号（ADR-0002 の改訂）。消えない（セーブは M3-5）。
- **地図のアイテム**: `items.json` の `revealsMap: true`。持っていると、パックのすべての部屋で、行っていないマスも別の色で見える。
- **地図の中身**（core の `roomMap(world, runtime)`、`GameSession.roomMap()`）: いる部屋の列数と行数、行ったマス、見えるか（地図のアイテム）、いまいるマス、出口のあるマス（出口の矩形の中心のマス。行ったマスか、見えるときだけ印を出す）。
- **メニュー**: 「ちず」は「もちもの」の次（3 行目。「せってい」は 4 行目）。その行を選んでいる間、右の窓に地図を出す（見るだけ。決定しても何も起きない）。マスは横 2：縦 1 の四角（画面の形）で、窓に収まる大きさ（大きすぎない上限あり）。行ったマスを塗り、見えるだけのマスは薄い色、いまいるマスの中に印、出口のマスに小さな印。何も無いマスは描かない。
- **色**: `ui.json` の `colors.map`（任意）: `visited`、`revealed`、`here`、`exit`。無ければ `text`、`dim`、`accent`、`cursor` を使う。
- **サンプルパック**: アイテム `map`（`@strings:item.map` は「ちず」/「Map」、`kind: key`、`revealsMap: true`、絵は 16×16 を所有者が Gemini で作る。届くまでは仮の絵）。`hub` の上段の右の棚に置く。拾うと「ちず を てにいれた」。

## 結果

- 交代の操作がメニューからもできる。入力にコマンドの欄ができ、M3-3 以降のアイテムの使用などにも使える。
- リプレイの形式が `version: 2` になる（`version: 1` も読める）。
- メニューの文字はパックごとに差し替えられる（フォントと色はパックのデータ）。

- 地図のアイテムの絵（所有者が Gemini で作る）。
- 地図の画面（実際のキャプチャで所有者が確認する）。
