# ADR-0018: 部屋の出口と部屋の移動

- Status: Accepted
- Date: 2026-11-23
- 論点: M3-1

## 背景

M3-1 で、部屋を増やし、`exits`（edge / door / warp）で部屋を移れるようにする。ADR-0007 では「コアが `TransitionRequest` を出し、ドライバが `sim.enterRoom()` を呼ぶ」とした。ADR-0009 では、移る間に入力を無視して止める tick 数（`transitionLockTicks`）を `camera.json` に置くとした。

所有者の確認（2026-11-23）:

- サンプルパックは 3 部屋にして、3 種類の出口をすべて使う。最初の部屋の右端から東の部屋へ（edge）、東の部屋の扉から 3 つ目の部屋へ（door）、3 つ目の部屋のワープで最初の部屋へ（warp）。一周できる。部屋の大きさは、カメラが動く M3-2 までは 1 画面のまま。
- 扉には、扉の前で**上**を押して入る（いまのボタン構成のまま使え、スマホでも押しやすい）。ADR-0007 の要確認（`confirm` か `up` か）はこれで決まる。
- 部屋を移るときは暗転する（約 0.3 秒）。移っている間は操作を受け付けない。長さはパックのデータで変えられる。
- 扉とワープの絵は所有者が Gemini で作る。届くまでは仮の絵で進める。所有者の判断（2026-11-23）で、仮の絵のままマージし、絵は届いたら別の PR で差し替える。
- はしご（M5-2）は M3-2 の後に前倒しする。上下の行き来は、はしごと部屋の上端・下端の出口で行う。
- マップは「ひとつながりの場所（屋外、洞窟など）は大きな 1 枚の部屋で書き、画面単位で切り替えて見せる（M3-2）。建物の中や別の地域は、扉やワープでつなぐ別の部屋にする」を基本にする。メモリは問題にならない（画面 100 枚分でも衝突データは数百 KB 程度）。

## 選択肢

部屋の移動をどこで処理するか。

| 案 | 概要 | 長所 | 短所 |
| --- | --- | --- | --- |
| 1 | ADR-0007 のとおり、コアは `TransitionRequest` を出すだけで、ドライバ（`GameSession`）が `enterRoom` を呼ぶ | 描画の演出とコアの状態を分けられる | リプレイを再生するところ（`GameSession`、`runReplayHeadless`、ソルバー）がすべて同じ手順を正しく書く必要がある。書き漏れると決定論が壊れる |
| 2 | 移動は `step` の中で完結させる。出口に触れた tick から「暗転して消える」「部屋を移る」「明るくなる」までを `World` の状態として持ち、`StepOutput.transition` は描画のための情報として出すだけにする | 入力列だけで結果が決まる（リプレイ、ブラウザと Node の一致がそのまま成り立つ）。ドライバは何もしなくてよい | `step` が少し複雑になる |

## 決定

案 2 を採る。ADR-0007 の「ドライバが `enterRoom` を呼ぶ」は、この ADR で置き換える。

### パックのデータ

- 出口は Tiled の `exits` レイヤの矩形（class `exit`）。プロパティは `kind: "edge" | "door" | "warp"`、`toRoomId`、`spawnId`、`effect?: "fade" | "cut"`、`requiresAnyTag?`（カンマ区切り）。
  - `effect` が無ければ `camera.json` の `roomTransition.effect`。`scroll` は M3-2 で決める（今は読み込み時に拒否する）。
  - `requiresFlag` はフラグ（M3-3）が入るまで読み込み時に拒否する。
  - `edge` の矩形は部屋の外周（左右上下のどれか）に接していなければならない（読み込み時に検査する）。
  - `toRoomId` と `spawnId` は存在しなければならない。行き先が同じ部屋でもよい。
- `camera.json` の `roomTransition?: { effect: "fade" | "cut", lockTicks: int >= 0 }`。無ければ `{ effect: "cut", lockTicks: 0 }`（演出も停止も無い）。サンプルパックは `fade`、20 tick（約 0.33 秒）。

### 出口に入る条件（`interaction`）

- 体（当たり判定の箱）が出口の矩形と重なっていて、
  - `edge` と `warp`: 重なっただけで入る。
  - `door`: 地上にいて、その tick に `up` を押した。
- `requiresAnyTag` があれば、操作中キャラクターの有効タグにそのどれかが無いと入れない（何も起きない）。
- **部屋に着いたときに体と重なっていた出口は、一度離れるまで入れない**（着いた途端に戻ってしまうのを防ぐ）。
- 同じ tick に複数の出口に入れるときは、部屋の `exits` の並び順で最初のもの。
- 同じ tick に HP が 0 になって交代や入口からのやり直しが起きたときは、出口に入らない（HP の処理が先）。

### 移動の段階（`World.transition`）

出口に入った tick を `t`、`lockTicks` を `L` とする。

- `fade`: 消える段階を `L >> 1` tick、明るくなる段階を残りの tick にする。`cut`: 消える段階を 0 tick、明るくなる段階を `L` tick にする（止まるだけで演出は無い）。
- 消える段階: 部屋はそのまま。シミュレーションは止まり（入力、操作、移動、HP、アニメーションを進めない）、`tick` だけが進む。
- 消える段階が終わった tick に部屋を移る（消える段階が 0 tick なら、出口に入った tick に移る）。
- 明るくなる段階: 新しい部屋で、同じく止まる。終わった次の tick から、ふつうに操作できる。
- 止まっている間の入力は捨てる（ジャンプの先行入力なども残らない）。押し続けている入力は、止まり終えた tick からふつうに効く。

### 部屋に入るとき（`enterRoom`）

- `roomId` を変え、体の足元を行き先の spawn に置く。パーティの「部屋に入った位置」（`placement: 'spawn'` と、全員倒れたときに戻る場所）もこの spawn にする。
- `edge` は速度を保つ（走って、または跳んで抜けた勢いのまま次の部屋に入る）。`door` と `warp` は速度を 0 にする。
- 向きは保つ。攻撃、すり抜け降下、触れている HP が減るタイルの状態は打ち切る。HP は保つ。
- 新しい部屋で接地しているかを計算し直す（`createWorld` と同じ）。
- スプライトは補間しない（`teleported`、ADR-0003）。
- 入った spawn の id を `World.party.spawnId` に持つ。操作感の切替（M2-3）で「部屋の入口からやり直す」ときは、いる部屋のこの spawn から新しく始める（`GameSession.roomEntrance`）。
- 止まっている間も `tick` は進むので、tick で数える時間（コヨーテタイム、着地の硬直など）は止まっている間も過ぎる。

### 出力

- `RenderSnapshot` に `room`（部屋 ID）を足す。描画は部屋が変わったらタイルを作り直す。
- `StepOutput.transition`: 移動中は `{ effect, phase: 'out' | 'in', tick, ticks }`（その段階の何 tick 目か、段階の長さ）、移動していなければ `null`。描画はこれで画面を暗くする（`fade` のときだけ。消える段階で 0 から 1、明るくなる段階で 1 から 0）。HUD は暗くしない。

### hash（ADR-0002）

`party` の最後に `spawnId`、`animation` の後、`flags` の前に `transition`（段階、残り tick、行き先の部屋、spawn、出口の種類、効果）と、入れない出口の番号の列を足す。

### ソルバー（ADR-0015）

ソルバーは部屋 1 つを解くので、解く部屋の出口を取り除いた `PackRuntime` で探索する（出口で部屋を出ていく経路は A-3 で扱う）。

## 結果

- リプレイ、ブラウザと Node の一致、golden は、部屋の移動を含めてそのまま成り立つ。
- 部屋の上端と下端にも `edge` の出口を置ける。落ちると下の部屋、上の部屋へははしご（M3-2 の後）で上がる。
- 大きな 1 枚の部屋は、M3-2 のカメラが入れば書ける（衝突データの大きさに実用上の上限は無い）。
